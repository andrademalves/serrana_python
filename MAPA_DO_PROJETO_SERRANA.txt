1) VISÃO GERAL
================================================================================

OBJETIVO DO SISTEMA:
O Sistema Serrana é uma solução empresarial completa para gestão de obras,
orçamentos, vendas diretas, estoque, financeiro e projetos. O foco principal
é o ciclo completo: ORÇAMENTO → PROJETO/OBRA → CUSTOS → RECEBIMENTOS.

O sistema gerencia desde a visita técnica inicial, passando pelo orçamento
comercial, aprovação, execução da obra com controle de custos e receitas,
até o fechamento financeiro e análise de lucratividade por projeto.

PRINCIPAIS MÓDULOS DO MENU LATERAL:

1. OBRAS & PROJETOS (app: projetos)
   - Orçamentos: Criação de propostas comerciais com múltiplos itens
   - Projetos/Obras: Gestão de projetos aprovados (centro de custo)
   - Vendas Diretas: Vendas simples de produtos sem vínculo com obras
   - Visitas Técnicas: Agendamento e controle de visitas antes do orçamento
   - Diário de Obra: Registro diário de atividades, equipe, materiais

2. ORÇAMENTOS (app: vendas - NOVO MÓDULO PARALELO)
   - Sistema comercial profissional com orçamentos mais robustos
   - Condições de pagamento predefinidas
   - Geração automática de obras e títulos financeiros
   - Análise de margem e custo estimado
   - NÃO ENCONTRADO: Integração completa ainda em desenvolvimento

3. VENDAS DIRETAS (submódulo de projetos)
   - Venda rápida sem orçamento prévio
   - Movimentação automática de estoque
   - Geração de títulos a receber (PENDENTE)

4. VISITAS TÉCNICAS (submódulo de projetos)
   - Registro de visitas antes do orçamento
   - Controle de custos e valores cobrados
   - Possibilidade de converter valor em desconto no orçamento

5. GESTÃO (app: cadastros)
   - Pessoas: Clientes, Fornecedores, Funcionários, Vendedores
   - Produtos e Serviços
   - Estados e Cidades

6. FINANCEIRO (app: financeiro)
   - Contas a Pagar e Receber
   - Bancos e Contas Financeiras
   - Centros de Custo (vínculo com projetos/obras)
   - Plano de Contas
   - Régua de Cobrança automática
   - Budget (controle orçamentário)

7. RELATÓRIOS
   - Resultado por Obra (receitas vs custos)
   - Dashboard BI (app: dashboard)
   - Relatórios de vendas e conversão (app: vendas)

8. ESTOQUE (app: estoque)
   - Controle de itens (materiais, produtos acabados)
   - Movimentações de entrada/saída
   - NÃO ENCONTRADO: Integração automática com orçamentos

9. SISTEMA (app: usuarios)
   - Usuários e permissões
   - Empresas (multiempresa)
   - Módulos e menus personalizados
   - Backups

================================================================================

----------------------------------------------
A) CRIAR ORÇAMENTO → GERAR PARCELAS → SALVAR
----------------------------------------------

MÓDULO: projetos (app antigo)

1. Usuário acessa: /projetos/orcamentos/criar/
2. Preenche formulário (cliente, vendedor, data, validade)
3. Adiciona itens dinamicamente (JavaScript + Formset Django):
   - Seleciona tipo (PRODUTO/MATERIAL/SERVICO/MAO_OBRA)
   - Busca item via Select2 (AJAX: buscar_itens_por_tipo)
   - Select2 retorna formato "tipo_id" (ex: "produto_5", "item_12")
   - Preenche quantidade, valor unitário, desconto
   - JavaScript calcula subtotal automaticamente
4. Aplica desconto global (NENHUM/PERCENTUAL/VALOR_FIXO):
   - Model.save() calcula desconto em R$
   - Calcula valor_final = valor_total - desconto
5. Adiciona parcelas:
   - Número da parcela, descrição, vencimento, valor, forma_pagamento
   - JavaScript valida soma das parcelas
6. Salva orçamento:
   - View criar_orcamento valida form + formset_itens + formset_parcelas
   - Calcula valor_total somando itens válidos
   - Salva Orcamento com código auto (ORC-2026-0001)
   - Salva itens (busca código do item via item_ref)
   - Salva parcelas
   - Registra histórico (OrcamentoHistorico)
7. Redireciona para visualizar_orcamento

PROBLEMAS ATUAIS:
- Item do orçamento aceita FK para Item (estoque) mas produtos estão em Produto
- item_ref é string "tipo_id" mas não é validado consistentemente
- Desconto global calculado no save() mas não valida se é > valor_total
- Soma das parcelas não é validada no backend (só no JS)
- Não gera títulos financeiros automaticamente

E) RELATÓRIO "RESULTADO POR OBRA"
----------------------------------------------

CÁLCULO ATUAL (baseado em ContaCorrenteProjeto):

1. Listar todos os projetos
2. Para cada projeto:
   RECEITAS:
   - Soma ContaCorrenteProjeto.filter(tipo=RECEBIMENTO).aggregate(Sum(valor))
   
   CUSTOS:
   - Soma ContaCorrenteProjeto.filter(tipo=PAGAMENTO).aggregate(Sum(valor))
   - OU Soma AlocacaoProjeto.aggregate(Sum(valor_total))

   - Margem R$ = Receitas - Custos
   - Margem % = (Margem / Receitas) * 100
   
   COMPARAÇÃO COM ORÇADO:
   - Valor Orçado = Projeto.valor_orcado
   - Desvio = Valor Contratado - Valor Orçado

PROBLEMA:

----------------------------------------------
CÁLCULO DE SUBTOTAL POR ITEM
----------------------------------------------

ONDE: OrcamentoItem.save() (projetos/models.py linha ~197)

LÓGICA:
1. Garantir valores não-nulos:
   - quantidade = quantidade ou Decimal('1.000')
   - valor_unitario = valor_unitario ou Decimal('0.0000')
   - desconto = desconto ou Decimal('0.00')

2. Calcular:
   subtotal = quantidade * Decimal(str(valor_unitario))
   valor_total = subtotal - desconto
